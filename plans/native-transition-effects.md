The parser walks RIFF `SFPD` → `fmt ` and `LIST clst` → `LIST chn ` → `chnh`, enforcing size and pad boundaries. Each record contains a fixed UTF-16 name and source UUID, then a length-bounded ordered component list. Most Sapphire components contain a complete length/count-checked parameter table. A parameter animation stores its displayed double, point count, and 52-byte point records containing source position, interpolation code, value, and two auxiliary numeric pairs. The pairs' meaning and code-to-curve-name mapping remain unverified. Their first numbers can lie hundreds of frames outside their associated key, so the parser does **not** call them Bezier handles. Some Vegas components have a different payload and remain opaque, with byte location and digest recorded.

The source key positions frequently end near the nominal frame count, but they are retained as raw numeric positions until their unit is established. The inventory records a **candidate** continuous normalization from the earliest to latest source key position across a record. It does not round keys to integer frames or claim exact source timing. `0` and `1` map to displayed frames `0` and `D−1` for an event of `D` frames. For `D=1`, the requested role chooses its endpoint.

## Current code path

1. `data/effects/templates/native_transition_presets.xml` supplies disabled Pending identities for all 194 source transitions. `EffectsRepository::assetDirs()` searches `effect-templates` and `effects`; `EffectsRepository::parseCustomAssetFile()` reads XML; `EffectTreeModel::construct()` creates browser categories and rows.
2. Browser drag/drop reaches `EffectStackView` or timeline effect application. `EffectStackModel::doAppendEffect()` selects group insertion; `copyXmlEffect()` calls `fromXml()` and pushes one undo command after success.
3. `EffectStackModel::fromXml()` retains the old clip-edge behavior for legacy templates. The new `native-v1` group branch preflights services/curve JSON, places filters across the whole selected event, and stores fitted-preset metadata. It is not yet certified for editable normalized source keys or all trim/split paths.
4. `EffectItemModel` creates an MLT filter and owns parameter/keyframe models. `EffectStackModel` attaches it to the timeline producer. Ordinary effects use `KeyframeModelList::resizeKeyframes()` during trims; the `native-v1` branch refits its filter range and event frame count but still needs proportional retiming of user-edited adjustment keyframes.
5. The Project Monitor displays frames from the timeline producer through its MLT consumer. The project writer serializes attached MLT filter properties; `EffectStackModel::fromMltXml()` rebuilds the editable stack on load.
6. Timeline previews invoke `kdenlive_render` for chunks. Final delivery passes a playlist to `kdenlive_render`, which invokes an external MLT render path. A native filter must be discoverable by the application and these processes.

The `getAnimationStringWithOffset()` path calls `serialize_cut(0, duration)` and stores integer key positions. It cannot serve as the authoritative continuous curve representation required for retimed presets. Existing effects and projects should continue using it unchanged; versioned native presets need their own curve representation and editing path.

`Wrap X/Y` code `2` corresponds to the screenshot's Reflect setting; code `0` corresponds to the documented No setting. Other numeric edge modes remain unknown. The official [Sapphire BlurMoCurves documentation](https://borisfx.com/documentation/sapphire/ofx/blurmocurves/) specifies shutter duration and shift in frames, curve sampling over the shutter interval, exposure bias, brightness, and No/Tile/Reflect wrap. The [VEGAS keyframe documentation](https://help.magix-hub.com/video/vegas/22/en/content/topics/8-design/keyframes.htm) describes interpolation families but does not establish the binary numeric code mapping used by these packages. The native renderer's own curve JSON uses separate, explicit codes: `0` linear, `1` Bezier, and `2` hold. Source codes must not be fed to that interface.

## Status rule and next gates

Every record currently has status **Pending**. Pending means application must be disabled until source parameters, required renderers, event fitting, edit/persistence behavior, and rendered validation pass. **Implemented** requires matching behavior and integration validation. **Equivalent** requires a rendered native reconstruction plus specific documented differences. The inventory retains all records, including looks outside eventual transition implementation scope, until scope is classified.

The native CPU module now provides separate Motion Transform and Blur, radial Fisheye Warp, seeded Shake, Axis Stretch, Perspective and Bulge Warp, and Spectral Chroma Warp services. They share source-pixel sampling and support reflected edges, subframe shutter sampling where applicable, and deterministic random access. The native radial, shake, bulge, and spectral weighting algorithms are reconstructions; their exact Sapphire functions are unknown. [Sapphire's WarpTransform documentation](https://borisfx.com/documentation/sapphire/ofx/warptransform/) describes independent X/Y scale, Z distance, and wrap modes. The added stretch service covers the actual non-default geometry in all 11 source instances, but its bilinear `Filter` sampling is not Sapphire's documented adaptive filter. [WarpCornerPin documentation](https://borisfx.com/documentation/sapphire/ofx/warpcornerpin/) describes four-corner perspective and Bulge X/Y, including 1 as undistorted; the native implementation uses a projective homography and a documented directional bulge approximation. [WarpChroma documentation](https://borisfx.com/documentation/sapphire/ofx/warpchroma/) specifies a sequence of spectral spatial transforms between red and blue, which the native multi-band renderer approximates with explicit RGB weights. Provisional linear source-key fixtures exercise the ordered Scroll, Stretch, and WarpPin chains, but they do not decode source interpolation codes. The next gates are that code mapping, non-Sapphire payloads, motion-vector processing for RSMB cases, full Kdenlive editing and whole-event persistence, and per-record rendered validation. Browser previews and active statuses follow those gates.
